template<class TransformTraits , class ComplexMultiArray1 , class ComplexMultiArray2 , typename DomainLengthType >
void suzerain::pencilfft::internal::transform_c2c ( const size_t  transform_dim,
const ComplexMultiArray1 &  in,
ComplexMultiArray2 &  out,
const int  fftw_sign,
const DomainLengthType  domain_length,
const int  derivative,
const unsigned  fftw_flags 
)

Perform a FFT on each 1D "pencil" of in storing the result in out.

If desired, the data can be differentiated. Processing is done in a way that attempts to minimize memory access under the assumption that either in or out will require non-stride-one access. If in and out are two distinct data sets, then in is not destroyed in the computation. Data is normalized in wave space in a transform-size-independent way.

Parameters
transform_dimzero-indexed dimension indicating the pencils to be transformed.
inan instance modeling the MultiArray concept containing the complex input data to transform.
outan instance modeling the MultiArray concept to contain the complex output data from the transform.
fftw_signeither FFTW_FORWARD or FFTW_BACKWARD to transform from physical to wave space or from wave space to physical space, respectively.
domain_lengthUsed when differentiating the data during the transformation.
derivativeIf nonzero, the data is differentiated during the transform process.
fftw_flagsFFTW planner flags to use when computing the transform. For example, FFTW_MEASURE or FFTW_PATIENT.
See also
The FFTW documentation for the expected wavenumber order in each 1D wave space pencil.
The FFTW documentation for information on the available planner flags.
Note
We choose to always use an intermediate buffer for the transform:
  • Avoids nuking in or out during FFTW planning
  • Allows us to always enforce FFTW memory alignment recommendations
  • Allows us to repeatedly apply the same, simple FFTW plan
  • Minimizes the costs of potentially non-stride-1 access
  • Always gives us in-place transform performance for the FFT
  • Greatly simplifies transform, dealiasing, and differentiation code
  • Simplifies moving to other FFT libraries in the future, e.g. ESSL
