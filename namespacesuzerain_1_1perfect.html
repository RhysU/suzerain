Accumulate the result of adding alpha times the manufactured solution msoln times beta times the given wave-space state swave.

Setting alpha=1 and beta=0 may be used to initialize a manufactured solution field. Setting alpha=-1 and beta=1 may be used to compute error against the manufactured solution. The manufactured solution lives on only the non-dealiased, non-Nyquist modes.

A complete Navier–Stokes apply_operator implementation.

The implementation is provided as a common building block for lowstorage::operator_nonlinear< contiguous_state<4,complex_t> > subclasses allowing varying numbers of passive scalars or varying hybrid implicit/explicit treatment. Such subclasses feature an overwhelming amount of redundancy and are error prone to create. This implementation allows writing the "futsy" bits once and then sharing the logic repeatedly. Templating allows for compile-time branching amongst different implementation choices rather than paying runtime cost for such flexibility.

Computation follows the "Numerical Considerations" section of writeups/perfect_gas.tex. No boundary conditions are applied. Gathers information required per operator_common_block documentation.

Parameters
scenarioNondimensional scenario parameters.
oProvides access to discretization and parallel decomposition operational details.
commonShared storage for interaction with an linear_operator implementation providing forcing and boundary conditions.
sgSlow growth forcing to be applied via the Largo library.
msolnIf msoln evaluates to true in a boolean context, then it will be used to provide manufactured forcing terms.
timeSimulation time at which the operator should be applied. This allows time-dependent forcing (e.g. from msoln).
swaveState to which the operator should be applied. On entry, it must be coefficients in the X, Y, and Z directions. on exit, it must be coefficients in the X and Z directions but collocation point values in the Y direction.
methodLow-storage timestepping scheme used to compute a stable time step when ZerothSubstep == true.
substep_indexThe index of the current substep being taken.
Template Parameters
ZerothSubstepShould one-time activities taking place at the beginning of a Runge-Kutta step be performed? Examples include computing a stable time step size and also computing reference quantities for linearization.
LinearizeWhat type of hybrid implicit/explicit linearization is employed?
SlowGrowthIs slow growth forcing being applied?
ManufacturedSolutionWhat manufactured solution should be used to provide additional forcing (when enabled)?
Returns
A vector of stable timestep sizes according to different criteria per lowstorage::operator_nonlinear::apply_operator.
See also
lowstorage::operator_nonlinear for the (slightly different) interface that an actual operator would provide.
